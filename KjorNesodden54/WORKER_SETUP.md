# Worker operations: setup and limitations

This change depends on pull request #20. Merge and release the address/order changes before this worker branch, then deploy the updated `firestore(4).rules` using the `firebase.json` in this directory. Rebuild and release the app for both customers and workers: customers on the previous version can still submit orders, but their orders lack the new assignment fields. An admin must open Bestillinger and select “Gjør eldre bestilling tilgjengelig for sjåfører” for those orders.

An admin can create or deactivate a worker from the home screen. Workers use their email and password to sign in. If authentication account creation succeeds but the Firestore write fails, retry with the same email and password. Deactivation immediately blocks Firestore worker operations. The admin should communicate credentials securely and ask workers to change their temporary password.

Workers can take multiple deliveries, reorder them on their own device, navigate to the delivery point or search for the pickup by restaurant name, and mark the assigned order picked up, on the way and delivered. An admin must mark the order ready before pickup. Admins can release an assigned order before pickup; after pickup it must be handled manually. The order list and history are Firestore-backed, while manual order sequence is stored locally on the worker's device. The pickup search should be checked before navigating; the current restaurant records have no verified street addresses or pickup coordinates. Distance calculation, live tracking, ETA and automatic per-restaurant pickup status are not included. Fee approval and notifications are described in PRICING_NOTIFICATIONS_SETUP.md.

The Firestore emulator tests cover simultaneous assignment, deactivation, ownership restrictions and legacy orders; run `npm run test:worker:rules` with Java and Firebase CLI available. Test the complete workflow with real devices and a non-production Firebase project before deployment. Account creation uses Firebase Auth email/password and requires that provider to be enabled. Firebase Auth and Firestore cannot be created in a single transaction.
